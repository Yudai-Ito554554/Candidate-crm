# Candidate CRM 本番移行 Go/No-Go チェックリスト

最終更新: 2026-08-11（Asia/Tokyo、staging独立アプリでの権限UATを反映）
Release Candidate baseline: `91ef650`

## 使い方

- 判断は**3段階**に分けて行う。各段階は前段階のGoを前提とする。
  - **Stage 1**: セキュリティ修正2migration（`email_threads`/`files`の列権限）のみを本番適用する
  - **Stage 2**: プロジェクトオーナー本人によるmacOSでの内部利用を開始する
  - **Stage 3**: 外部顧客へmacOS/Windows版を一般提供する
- 各段階の「重大項目」が1つでも未チェック（未確認・失敗）の場合、その段階は**No-Go**と判定する。後段階の重大項目は前段階がGoになるまで評価しない。
- Windows実機確認・コード署名は**Stage 3のみ**の重大項目とし、Stage 1・Stage 2を妨げない。
- 「推奨」区分は、どの段階のGo判定も妨げないが、リリース判断者へ既知の制限として共有する。
- このチェックリストの記入だけでは本番への変更は一切行われない。実際の適用作業は [`docs/production-release-runbook.md`](./production-release-runbook.md) に従う。
- 空欄のまま「Go」と判定しないこと。各項目は実施者・確認者の記名と日時を記入する。
- **認証・セッション層の設計変更は、未完了項目の検証方式を無効化しうる。** この層に触る設計をレビュー・実装する際は、未完了項目が依存している前提を先に確認すること。2026-08-19、Batch 5のセッション設計変更がS3-3の検証方式を無効化した実例がある（`docs/fable5-decision-s3-3-2026-08-19.md` 6節）。
