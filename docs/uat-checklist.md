# Candidate CRM 業務受け入れテスト

このチェックリストは、架空データだけを使ってmacOS・Windowsの未署名QA版を確認するためのものです。実在する候補者、企業、メール、履歴書は入力しません。

## 1. テスト準備

- admin、agent、viewerのテストユーザーを1名ずつ用意する
- Supabaseの対象が非本番プロジェクトであることを確認する
- 各OSで1280×800以上の画面を使用する
- テスト開始前にブラウザの開発者コンソールへ認証情報や業務データが出ていないことを確認する

## 2. 認証と権限

- 未ログイン時にCRM画面が表示されず、ログイン画面だけが表示される
- ログイン、ログアウト、アプリ再起動後のセッション復元が動作する
- パスワード再設定と招待リンクが`candidate-crm://auth/callback`でアプリへ戻る
- pendingユーザーは業務データを閲覧できない
- viewerには登録・編集・アーカイブ・復元・AI生成操作が表示されない
- URLを直接入力してもviewerは編集画面を開けない
- adminだけが利用者ロールと監査ログを操作・閲覧できる

## 3. 日常業務

- ホームで今日の対応、期限超過、返信待ち、最近見た候補者、KPIを確認できる
- 今日の予定とタスクで完了・再開・期限超過を識別できる
- Inboxで未対応、返信待ち、対応済みを切り替えられる
- 全体検索から候補者・企業・求人の詳細へ移動できる
- オフライン時に共通通知が表示され、再接続後に再取得できる

## 4. 候補者

- 候補者を登録・編集し、必須項目と日付の入力エラーを確認できる
- 氏名、メール、電話が既存データと一致する場合に重複警告が表示される
- 一覧・パイプラインを切り替え、行またはカードから詳細へ移動できる
- パイプライン移動が保存され、失敗時には元の列へ戻る
- タイムライン、概要、職務経歴、求人・選考、タスク、ファイル、AIを切り替えられる
- 活動、職歴、タグ、求人提案、選考、タスク、ファイルを追加・更新できる
- 次回対応を完了すると、候補者から内容がクリアされ活動履歴に残る
- 候補者一覧の「データ取り込み」からUTF-8またはShift_JISのCSVを選択し、列対応・入力エラー・既存候補者との重複を確認できる
- CSV内で同じ氏名・メール・電話が重複する場合、後続行が初期の登録対象から外れ、別人と確認できた場合だけ手動で再選択できる
- CSVの登録対象行を一括登録し、候補者一覧へ反映される。入力エラー行は登録対象にできない
- 履歴書テキストを貼り付けると候補者フォームへ入力候補が反映され、修正・重複確認後に登録できる
- 5MB以内の文字入りPDFを選択すると端末内で文字抽出され、同じ確認フォームへ反映される。画像だけ・偽装・上限超過PDFは拒否される
- PDFと貼り付け原文がStorage、localStorage、外部AIへ自動送信・保存されない
- AIサマリー生成後も、担当者が確認するまで業務判断へ利用しない案内が表示される
- アーカイブと復元が動作し、物理削除されない

## 5. 企業と求人

- 企業、採用担当者、求人を登録・編集できる
- 企業名・Webサイト、同一企業内の求人名で重複警告が表示される
- 企業詳細で担当者、求人・選考、活動、ファイル、タグを確認できる
- 求人詳細から候補者を提案し、候補者側にも同じ選考が表示される
- 参照中の企業・担当者・求人はアーカイブできない
- 親企業がアーカイブ済みの求人は復元できず、企業の復元が先に案内される

### 5.1 求人票AI取り込み

架空データの`docs/fixtures/job-import-sample.txt`と`output/pdf/candidate-crm-job-import-sample.pdf`を使用する。実在する求人票や非公開求人ページは、この非本番確認へ使用しない。

例外系は次の架空フィクスチャを使用する（すべて `node scripts/generate-job-import-uat-fixtures.mjs` で再生成できる）。

| ファイル                                                                                                                     | 用途                                                               | 期待される拒否メッセージ                                                       |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `docs/fixtures/job-import-fake.pdf`                                                                                          | 拡張子は`.pdf`だが中身はテキスト                                   | PDFの内容を確認できません。正しいPDFファイルを選択してください。               |
| `docs/fixtures/job-import-truncated.pdf`                                                                                     | `%PDF-`で始まるが`%%EOF`が無い                                     | PDFが壊れているか、読み込みが完了していません。別のPDFを選択してください。     |
| `docs/fixtures/job-import-password-protected.pdf`                                                                            | 実際にRC4-40で暗号化済み（ユーザーパスワード `uat-test-password`） | パスワード保護されたPDFは読み込めません。保護を解除したPDFを選択してください。 |
| `docs/fixtures/job-import-company-conflict.txt`                                                                              | 企業名とWebサイトを両方記載し、企業照合の競合を再現する            | （拒否ではなく既存企業の確認案内）                                             |
| `docs/fixtures/cache-variant-a/job-import-cache-variant.pdf`<br>`docs/fixtures/cache-variant-b/job-import-cache-variant.pdf` | 同名・同容量（1,223バイト）で内容が異なるPDFの組                   | （拒否ではなくキャッシュ誤再利用の検出）                                       |

- テキスト貼り付けで企業名、求人名、事業部、職種、雇用形態、勤務地、年収、募集期間、条件、仕事内容が候補として表示される
- PDFをファイル選択またはドラッグ＆ドロップし、ファイル名・容量を確認してから同等の項目を読み取れる
- macOS・WindowsのTauriアプリ双方でPDFのドラッグ＆ドロップが反応する
- 複数PDFを同時にドロップすると1件ずつ選択する案内が表示され、先頭ファイルだけが勝手に使われない
- 選択中のPDFを解除するとAI読み取りボタンが再び無効になる
- 公開URLはログイン不要のHTTPS求人ページだけを使用し、社内限定URLや認証付きURLを送信しない
- AI実行前に文字数、PDF形式・5MB上限、URL形式の不備が表示され、無効な状態では実行できない
- `.pdf`拡張子でも内容がPDFでないファイルはAI実行前に拒否され、利用枠を消費しない
- Edge Functionへ直接送信した偽装PDFや、PDFを名乗る不正な公開URLもOpenAI送信前に拒否される
- 先頭がPDF形式でも末尾の`%%EOF`がない不完全ファイルは、壊れている可能性を案内して拒否される
- パスワード保護されたPDFは保護解除を案内し、AI利用枠を消費せず拒否される
- 読み取り中は入力元を変更できず、完了後に差分・未取得項目・注意事項を確認できる
- 読み取り結果に「入力元」が表示され、テキスト、PDFファイル名、公開URLのホスト名を区別できる
- 取得した各項目の直下に求人票原文の短い根拠が表示され、値と記載内容を登録前に比較できる
- 根拠引用のない項目は「根拠未確認」と表示され、求人票を直接確認したチェックを入れるまで反映できない
- 「根拠ありだけ選択」で引用のある項目だけが選択され、根拠未確認の項目が反映対象から外れる
- 入力済み項目の変更・クリアは初期選択されず、明示的に選択した場合だけ反映される
- AIの注意事項がある場合、確認チェックを入れるまで反映できない
- 未登録企業は自動作成・自動選択されず、企業欄が不足項目として表示される
- 未登録企業名を確認してボタンを押すと企業を登録し、求人の企業欄へ選択できる
- AIが取得した未登録企業名を修正して登録でき、空欄では登録ボタンが無効になる
- 求人票に業種・Webサイトが明記されている場合だけクイック登録欄へ候補表示され、確認・修正して企業名と一緒に登録できる
- WebサイトがURL形式でない間はエラーが文字で表示され、企業登録ボタンが無効になる
- 企業名またはWebサイトが登録済み企業と一致する場合は重複作成せず、その企業を選択する
- 企業名とWebサイトが別々の既存企業に一致する場合は自動選択せず、既存企業の確認を案内する
- 照合が競合した場合は該当企業と「企業名一致」「Webサイト一致」が並び、正しい既存企業をその場で選択できる
- 登録済み企業の候補が表示されている間は新規企業を作成できず、候補選択でも企業マスタが変更されない
- AI読み取り結果で企業照合が競合した場合は、正しい既存企業を選択するまで反映ボタンが無効になる
- 既存企業を選択すると企業欄が反映項目へ追加され、他の求人項目と一度に反映できる
- 企業名の表記が異なってもWebサイトが1社と一致する場合は、照合理由を表示してその既存企業を反映候補にする
- AIが返したWebサイトがHTTP・HTTPSの有効なURLでない場合は、既存企業の照合へ使用しない
- 「既存企業から選ぶ」でクイック登録を中止し、通常の企業欄へフォーカスできる
- 反映後に反映件数・保留件数・未登録状態が表示され、不足中の必須項目へフォーカスする
- 同じ求人票の再読み取りでは画面内キャッシュが使われ、追加のAI実行が発生していない旨が表示される
- 同名・同容量でも内容が異なるPDFは、前回の読み取り結果を誤って再利用しない
- 「入力とキャッシュを消去」で元データ、結果、画面内キャッシュが消え、通常フォームへ反映済みの値は残る
- AI反映後も通常の「求人を登録」を押すまでデータベースへ保存されない

## 6. データ保護

- 候補者、企業、求人の入力途中に画面を離れると確認が表示される
- ファイルは非公開Storageからだけ取得され、公開URLが生成されない
- localStorageに候補者情報、閲覧履歴、メール本文、ファイル情報が保存されない
- 監査ログに本文や変更前後の値が複製されず、対象・操作・変更フィールドだけが残る
- AI入力に氏名、メール、電話、生年月日、private notesが含まれない

## 7. デスクトップ確認

- ウィンドウを1280×800にしてもページ全体に横スクロールが出ない
- サイドバーの折り畳み、キーボード操作、フォーカス表示が動作する
- macOSで起動、終了、再起動、ディープリンクを確認する
- macOSでログイン後に終了・再起動しても再ログイン不要で、Keychainにrefresh tokenだけが保存される
- macOSでログアウトするとKeychainの`supabase-refresh-token`エントリが削除される
- 旧版localStorageセッションから初回移行後、該当する`sb-<project-ref>-auth-token`キーが残らない
- Keychainアクセスを拒否してもクラッシュせず、平文保存へフォールバックしない
- staging版とproduction版を共存させ、資格情報とログイン状態が混在しない
- Windowsでインストール、起動、終了、再起動、アンインストールを確認する
- Windows実機入手後、Credential Managerでログイン復元・ログアウト削除・staging/production分離を確認する（Batch 5のmainマージ条件外）
  - ログイン復元・ログアウト削除は2026-08-17に確認済み。staging/production分離はWindows実機にproduction版が未インストールのため未実施。production版をWindowsへ導入する際に実施する。macOSでは2026-08-14に確認済みで、環境ごとのservice名分離は自動テストでも固定されている
- 未署名QA版であることをテスターへ明示し、一般配布しない
